# Enterprise Agent Platform · 企业智能体平台

面向中小企业的智能体管理系统：把财务、工资人事、生产供应链、待办预警、企业知识库装进一套系统，网页管理台 + 飞书双入口，AI 智能体贯穿其中。已在真实企业场景生产运行。

## 立项背景

中小企业普遍用不起 ERP，但痛点真实存在：

- 财务靠人工台账，报销审批纸质流转，月底对账翻 Excel；
- 生产物料、批次效期没有系统管，临期风险靠人盯；
- 工资每月手工算个税，工资条靠群发；
- 证照到期、征期、社保增减员等义务事项全靠负责人记性。

这类企业往往已经在用飞书/钉钉做协作。本项目的思路：**以企业 IM 为入口、以大模型智能体为交互层、以轻量自建账本为事实源**，用一套可复制的平台解决这些问题，成本远低于传统 ERP，上手门槛是"会聊飞书"。

## 总体架构

```
飞书（私聊智能体 / OA 审批 / 审批卡片 / 每日简报 / 工作台应用）
        │  WebSocket 长连接（免公网回调）
        ▼
┌─────────────────────────────────────────────────┐
│  NestJS 后端（本仓库 server/）                    │
│  ├─ 财务域：台账/票夹/审批落账/对账/报表           │
│  ├─ 工资域：名册/工资单/个税累计预扣/工资条私聊     │
│  ├─ 供应链域：物料/库存批次效期/采购/预警          │
│  ├─ 义务域：12 类扫描器/每日简报/责任路由          │
│  ├─ 对话域：多会话/按人隔离/文件工作区             │
│  ├─ 知识库域：MCP 接入 kb-rag（带出处问答）        │
│  ├─ 融合层：平台适配器（飞书已实现/钉钉同构接口）    │
│  └─ RBAC 权限点 + 全路径审计 + JWT 鉴权            │
└────────────┬────────────────────┬───────────────┘
             │ SDK 子进程网关      │ MCP stdio
             ▼                    ▼
      DeepSeek Harness          kb-rag 知识库
      （开源 Agent 框架，        （本地嵌入，语料
        Agent 工具插件层）         不出域）
             │
             ▼
        SQLite 账本（唯一事实源，金额存分，每日自动备份）
```

- **大脑与账本分离**：Agent 运行时用开源框架（DeepSeek Harness，"一切皆插件"），上游源码零改动；业务能力全部做成工具插件 + REST 双通道。
- **账本是唯一事实源**：AI 永远不能直接写账——所有写操作走「提案 → 人工确认」两段式（审批通过 → 生成提案卡 → 负责人点确认才落账）。
- **平台适配器化**：融合层定义了平台无关的 adapter 接口，飞书是第一个实现，钉钉按同一接口复制。

## 关键设计决策

1. **权限 = 权限点拼装，不是预置角色库**。系统能力拆成 14 个权限点（finance:read/write、payroll:read/write、todo:read/write…），角色由企业在管理台自由拼装；新员工默认零权限，权限变更走飞书审批。这让平台从"给一家公司定制"变成"可复制交付"。
2. **AI 写账两段式**：审批落账、批量导入、工资落账，AI 只能生成提案，人确认才落库；agent 来源直接调落库接口一律 403。钱上的事，永远有人兜底。
3. **全路径审计**：所有写动作记录操作者、来源（ui/agent/confirm/bridge）与前后值；写失败、读拒绝同样留痕。审计不进前端界面（避免界面膨胀），唯一查询通道是对话工具。
4. **最小权限服务账号**：AI 子进程持有独立的 `agent-runtime` 角色（恰含所需权限点，无管理权），网关只为服务号签发运行时令牌；服务号缺位拒绝启动，不回退管理员身份。
5. **数据分割定版**：对话会话按人隔离（管理员不例外，404 不泄露存在性）；账本/工资按权限点共享；平台身份映射企业层管理。
6. **断线自愈三层**：连接监督器指数退避永不放弃 / 审批补抓（checkpoint+重叠窗口+重试队列）/ 十分钟低频重订阅自愈——飞书审批推送的"双层订阅"契约（后台加事件只是第一层，必须逐定义 subscribe，重复订阅返回 1390007 按成功处理）由此闭环。
7. **卡片 3 秒 ack 契约**：飞书卡片回调要求 3 秒应答，实现为 handler 先返回终态卡，业务异步完成。
8. **评测与对抗审查文化**：后端 389 个自动化测试全绿（域语义+HTTP 全链路+假进程网关回归+越权反例）；每个批次交付前跑"无上下文对抗审查"（由无开发上下文的 AI 专门挑毛病），累计抓出并修复数十个真实缺陷。

## 快速开始

### 前置依赖

- Node.js ≥ 20（npm）；前端 pnpm
- [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（开源 Agent 运行时，对话网关的上游；`ADMIN_DSH_BIN` 指向其可执行文件）
- 可选：kb-rag（本地知识库 RAG 框架，MCP 接入）、飞书自建应用（融合层）

### 后端

```bash
cd server
npm install
# npm 12 需批准 better-sqlite3 原生构建：
npm install-scripts approve better-sqlite3 && npm rebuild better-sqlite3
npm run build        # 必须走 tsc（装饰器元数据；tsx 直跑会全线 500/401）
npm start            # http://127.0.0.1:3210（仅本机）
npm test             # 389 用例
```

环境变量见 [`server/.env.example`](server/.env.example)（全部可缺省运行：JWT 密钥自动生成、数据目录自动落 `~/.dsh/company-data/admin`）。

### 前端

```bash
cd web
pnpm install
pnpm dev             # apps/web-antd，开发端口 5666，代理后端 /api
```

### 飞书接入（可选）

1. 飞书开放平台创建企业自建应用，开通长连接订阅（免公网回调）；
2. `ADMIN_FEISHU_APP_ID` / `ADMIN_FEISHU_APP_SECRET` 走环境变量（不进任何文件）；
3. 前端登录页替换 [App ID 占位符](web/apps/web-antd/src/views/_core/authentication/login.vue)；
4. `ADMIN_BRIDGE_ENABLED=1 ADMIN_BRIDGE_ADAPTER=feishu` 后重启，身份白名单默认拒绝，需在管理台逐个放行。

### 部署（macOS launchd）

`launchd/` 目录提供常驻服务与每日备份的 plist 模板、安装说明；`server/scripts/backup-db.sh` 每日在线备份+校验+保留 30 份。

## 安全边界

- 凭据只走环境变量，不进代码仓、不进文档；`.gitignore` 排除 `.env*`、`*.db`、密钥文件；
- 账本数据存仓库外数据目录，仓库内无任何业务数据；
- 飞书 App ID 是公开值（授权码模式的公开参数），App Secret 在服务端；
- 测试夹具使用合成数据（供应商A/王小明等），与任何真实企业无关。
